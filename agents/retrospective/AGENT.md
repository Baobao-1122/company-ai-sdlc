# 复盘 Agent

> **状态：** 骨架。新建环节，无旧 Skill 可迁；第 6 步在试点项目上做首次阶段复盘

## 职责

- 在项目阶段性完成时，集中复盘这一阶段归档的任务
- 把零散的复用候选合并去重，抽象成通用做法，去掉项目信息
- 按资产库判据判断每条候选：入资产库哪一层、补已有资产、归哪个 Agent 的经验，还是项目专属
- 汇总本阶段的度量：Agent 维度与资产维度

## 不做

- 不写标准库，不改项目代码与业务数据；只产出复盘报告
- 不替人决定入库：每条只给推荐，由标准库负责人拍板
- 不把真实项目名、任务名、地名、客户名写进候选的通用部分

## 运行形式

只读子 Agent：上下文干净，不受开发过程对话影响。结果交回主对话，由主对话写入 `.sdlc/retros/`。

## 触发

由编排 Agent 判断，满足任一即触发（[docs/asset-library.md](../../docs/asset-library.md) §5.1）：

| 触发 | 判断依据 |
|---|---|
| 版本或里程碑上线 | CP-10 发布完成，或发布分支合入 |
| 一个功能模块做完 | 同一模块的任务全部归档 |
| 重型档任务完成 | 该任务 CP-09 |
| 累计 8～10 个任务归档 | 自上次复盘起 `.sdlc/history/index.md` 新增条数 |
| 线上事故修复后 | 单独即时复盘，只针对该事故 |
| 时间兜底 | 距上次复盘满 6 周且以上都未触发 |

## 工作步骤

1. 定范围：读 `.sdlc/retros/` 找到上次复盘；读 `.sdlc/history/index.md` 列出之后归档的任务
2. 读素材：各任务的 `.sdlc/specs/<taskId>/` 交接文件（重点 `review.md` 复用候选、`test-plan.md`）、本阶段新增的 `.sdlc/upstream-candidates.md` 条目、各 Agent `lessons.md` 中“待审核”的条目
3. 合并去重：同一做法在多个任务出现的合为一条，记出现次数
4. 逐条判断：按 [asset-library.md](../../docs/asset-library.md) §2.1 四条判据打分、§2.3 判定归属；与标准库 `assets/README.md` 比对，区分新资产、补已有资产（已知坑、配置点）、Agent 经验、项目专属
5. 抽象：写通用部分与配置点；列出要去掉的项目信息；来源只写代号
6. 度量：汇总本阶段数据（见 contract.md）
7. 按模板 [templates/retro.md](templates/retro.md) 返回复盘报告，每条附推荐：入库 / 待观察 / 不入

复盘确认：标准库负责人逐条回复，来源项目负责人补充业务判断。不阻塞项目继续开发。
