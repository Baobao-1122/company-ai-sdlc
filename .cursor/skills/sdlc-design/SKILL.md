# SDLC 阶段 2：设计拆分

## AI 引导职责

- 进入时：`✅ 已收到确认 → 进入 **阶段 2 · 设计拆分**`，预告 CP-02
- 回复开头：`📍 阶段 2/5 · 设计拆分`
- 结束：**CP-02 决策包**（判据：业务项目 `docs/qa/ai-sdlc-decision-rubrics.md` §3 CP-02；标准库 `docs/decision-rubrics.md`）

## Task State

- 进入时 **Read** `.sdlc/task-state.yaml`；`cp.cp01` 须为 `passed` 或 `skipped`
- 用户 CP-02「开始实现」后 **Update**：`cp.cp02: passed`，`stage: implement`

## 前置

CP-01 已通过，或用户明确需求已确认

## CP-02 输出结构

须含 ①～⑤ 五块；② 判据表 + ③ 自检 + ④ 推荐不可省略。

若修改数据库 schema，设计内容还须列出 migration、目标验收环境、应用命令、结构检查、依赖 API 冒烟和回滚方式；缺任一项时 CP-02 推荐 **Stop**。

若命中**业务数据影响面**（查询/筛选语义、归属/归因、聚合、金额/电量口径、可见范围等），还须列出**只读**抽样对账计划（样本、指标、基线、通过标准）；并写明校验禁止改删数据、产出为结论与问题。缺计划或计划含写库时推荐 **Stop**。

```markdown

（设计内容：文件清单、验收命令、commit 拆分）

### 数据库变更计划（涉及 schema 时必填）
- migration：…
- 目标验收环境与应用命令：…
- 结构检查与依赖 API 冒烟：…
- 回滚或恢复方式：…

### 业务数据影响计划（命中时必填；未命中写「无」+ 理由）
- 影响面：…
- 只读抽样：样本 / 指标 / 基线 / 通过标准
- 红线：校验禁止 INSERT/UPDATE/DELETE；只出结论与问题

### ① 本卡点目的
…
### ② 判断要点
…
### ③ Agent 自检
…
### ④ Agent 推荐
…
### ⑤ 请你回复
1. **「开始实现」**  2. **「调整范围：…」**  3. **「暂停」**

⏸ **CP-02 设计暂停**
```

## 禁止

- 未过 CP-02 写代码
- CP-02 无判据/自检/推荐
- 修改 schema 但未设计 migration 应用与运行时验证
- 命中数据影响面但无只读抽样计划，或以校验名义设计写库修数
