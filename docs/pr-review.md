# 合并前 PR 审查（Agent Review + 人工 Merge）

> **文档 ID：** `PR-REVIEW-v1`  
> **受众：** Cursor Agent + 研发人员  
> **最后更新：** 2026-10-24

业务项目把本文件复制为 `docs/qa/ai-sdlc-pr-review.md`。集成分支名以项目为准，下文用 `dev` 指集成主分支。

---

## 1. 这条流程解决什么

写代码的 Agent 不能代替审查。PR 审查由 **另一次只读审查** 完成：对 `origin/dev...HEAD` 跑 Bugbot（命中安全路径时再跑 Security Review），输出审查结论，再开或更新 PR。

Harness 和 Bugbot 证明测试与代码风险。它们不证明业务口径。业务口径只在项目声明了 **可验算业务结果** 时才进入本流程。

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| 写代码的 Agent | 在功能分支完成实现、harness、CP-06 | 不把自己读 diff 的结论当成 PR 审查 |
| PR 审查 Agent | Bugbot 整分支 diff、写结论、开 PR、停在 CP-08 步骤 1 | 默认同轮不 `gh pr merge`、不 push `dev` |
| 人 | 读结论；命中可验算结果时回答口径题；再决定 Merge | 不在没有结论时合并 |

**同轮禁止 Merge：** `gh pr create` 与 `gh pr merge` 不得在同一轮执行。开 PR 后停在 CP-08 步骤 1。用户说「push 并合并」只授权 push 和开 PR。

---

## 2. 何时进入

用户说「提 PR」「开 PR」「合并 dev」「合进 dev」，且当前在功能分支、该分支已包含要通过的提交。

进入前须同时满足：

1. 当前不是 `dev` / `main` / 生产镜像分支
2. 分支已 push，或本轮先 push 再审查
3. 相对 `origin/dev` 有提交
4. 该分支上的项目验证命令（通常 `test:harness:ci`）已通过；过期则审查前重跑

缺任一条则停，不创建 PR。

---

## 3. 可验算业务结果

**可验算业务结果** 指：改动之后，可以用一条具体输入说出输出应变或不变。例如金额、权限允许或拒绝、对外字段取值、状态是否允许流转。

项目在 `AGENTS.md` §CP 判断扩展声明哪些改动算命中。未声明时，本仓库不替项目发明核对项。没有账单的项目不必做金额核对。

| 是否命中 | PR 结论必须写 |
|----------|----------------|
| 命中 | 改变的规则、影响范围、**一条会变的具体结果**、**一条不变的具体结果**、下面的人工判断块 |
| 未命中 | 一行「无需人工判断业务结果」。不编造数字题，也不要求人口径 |

两条结果都要有具体输入和输出。禁止只写「正常订单不受影响」而不给例子。样本优先用项目已有测试、只读查询或本次验证记录。没有样本时，结论为 ❌，写明缺哪条样本，不得建议合并。

---

## 4. 人工判断块

命中可验算业务结果时，聊天和 PR 正文都必须包含下面六行。人只看「请确认是否合并」时，审查不合格。

| 项 | 写什么 |
|----|--------|
| 为什么需要你判断 | 命中项目声明的哪一类结果 |
| 请你判断 | 一个可以回答是或否的问题 |
| 判断标准 | 项目已有口径；不在 PR 里新造标准 |
| 会变的结果 | 一条具体输入，以及改完后的结果 |
| 不变的结果 | 一条不该被这次改动影响的具体结果 |
| Agent 不能代决的原因 | 口径尚未由人确认，或样本不能单独证明口径 |

人的回复：

- 「口径接受」
- 「口径不接受：…」

未收到「口径接受」之前，不得建议合并，也不得执行 merge。未命中时不要输出这个块。

---

## 5. 审查结论

Bugbot（及适用时的 Security Review）完成后，聊天和 PR 正文使用同一结构。

```text
## PR 审查结论

- 审查级别：L1 Bugbot / L2 Bugbot + Security Review
- 对比范围：origin/<集成分支>...<分支名>（<n> commits）
- Bugbot 覆盖：完整 / 部分（未覆盖：<文件或提交>）
- 可验算业务结果：未命中 / 命中（<项目声明的类别>）
- 发现：Blocker <n> · High <n> · Medium <n> · Low <n>

### 会变 / 不变（仅命中时）

- 改变的规则：
- 影响范围：
- 会变：
- 不变：

### 人工判断（仅命中时）

- 为什么需要你判断：
- 请你判断：
- 判断标准：
- 会变的结果：
- 不变的结果：
- Agent 不能代决的原因：

### 问题清单

| 级别 | 位置 | 问题 | 建议 |
|------|------|------|------|
| — | — | 无 | — |

**总体结论：** ✅ 可合并 / ⚠️ 可合并但有保留 / ❌ 建议先修

**保留项：** （⚠️ 时必填；无则写「无」）
```

总体结论：

| 标记 | 条件 |
|------|------|
| ✅ | 无 Blocker/High；Bugbot 覆盖完整；未命中可验算结果，或已拿到「口径接受」且两条样本齐全 |
| ⚠️ | 只有 Medium/Low，或 Bugbot 只覆盖部分 diff。必须写出未覆盖范围和保留项 |
| ❌ | 有 Blocker/High、验证未过、命中可验算结果但没有两条样本，或口径不接受 |

Bugbot 明确只审了部分 diff 时，不得写 ✅。

## 6. CP-08

| 步骤 | Agent | 人 |
|------|-------|----|
| 1 | 贴完整结论和决策包，停住 | 未命中：「去 GitHub Merge」/「先修 PR」/「暂停」。命中：先「口径接受」或「口径不接受：…」，接受后再选合并或先修 |
| 2 | 仅当下一条明确授权 merge，且结论为 ✅ 或已接受的 ⚠️ | 默认自己在 GitHub Merge |
