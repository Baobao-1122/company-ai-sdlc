# 按业务选择技术栈

> 日期：2026-10-14  
> 用途：新项目或第一条架构决定时，先按产品形态选技术栈。  
> SDLC 流程对 Web 和引擎相同。接入脚本带上的 TypeScript 骨架是 Web 平台的工程入口，不代替这次选择。

## 变更记录

| 日期 | 版本 | 说明 |
|------|------|------|
| 2026-10-14 | v0.1 | 首版：Web 平台与引擎服务两套推荐 |
| 2026-10-14 | v0.2 | 引擎表写明门禁运行时是 Node.js 与 pnpm，与实现语言分开 |

## 1. 先看产品是什么

| 产品形态 | 用哪一套 |
|----------|----------|
| 有页面的业务平台、管理后台、运营界面 | Web |
| 规划、诊断、推荐、数值计算、同一输入必须重放的引擎服务 | 引擎 |
| 车联网接入、大量设备长连接上报 | 不在这两套里。用 Go 或 C++ 做接入网关，不把接入网关写成引擎 |

一个仓库只选一套作为实现语言。页面在别的业务平台时，引擎仓库不要为了接入脚本去用 Web 语言写计算。

## 2. Web 平台

适合订单、权限、页面和业务流转。

| 用途 | 选择 |
|------|------|
| 语言与运行时 | TypeScript、Node.js |
| 有页面 | Next.js |
| 无页面的纯接口 | 轻量 HTTP 框架。不装页面框架 |
| 入参校验 | Zod |
| 数据库 | PostgreSQL |
| 表访问 | Drizzle |
| 单测 | Vitest |
| 合并门禁 | `pnpm test:harness:ci` |

## 3. 引擎服务

适合沿既定输入做数值计算，并且同一输入、同一版本必须得到同一结果。补能规划、路径成本、诊断重算属于这一类。

| 用途 | 选择 |
|------|------|
| 实现语言 | Python 3.11。计算、接口和引擎单测都用它 |
| 接口 | FastAPI |
| 入参与契约模型 | Pydantic |
| 引擎单测 | pytest |
| 数据库 | PostgreSQL |
| 表访问与迁移 | SQLAlchemy、Alembic。有库时再安装 |
| 金额与物理量 | 十进制。不用浮点参与费用和电量 |
| 门禁运行时 | Node.js、pnpm。只跑合并门禁，不写计算 |
| 合并门禁 | `pnpm test:harness:ci`。由这条命令接入 pytest，不另换一条合并命令 |

Java 和 Go 留给业务平台和接入网关。第一版不把计算写成 C++。只有测量后单次计算超出时间要求，才把热点搜索抽到 C++，接口层仍用 Python。通用路径求解器只在产品确实要重排路径时再引入。

## 4. 怎么落进项目

架构决定写在该项目自己的技术文档里，写明选了哪一套、为什么。不要把另一套的框架装进本仓库。

SDLC 的阶段、暂停点和 `pnpm test:harness:ci` 两种产品都用。接入脚本生成的 TypeScript 检查可以留下，用来守住流程门禁。引擎的计算和单测仍按第 3 节。
