# 产品模版库

新需求进入阶段 1 时先读本索引。能覆盖这条需求的模版整份继承，对齐表只写本系统差异。不能覆盖的，按阶段 1 原来的方式对齐。

各系统填好的角色、权限和界面差异留在该项目的 PRD。本目录只放可继承的底稿。

## 索引

| 模版 | 文件 | 什么需求用它 |
|------|------|----------------|
| 登录与账号 | [login.md](login.md) | 登录、账号、角色、权限 |

## 使用

1. 需求阶段先读本索引。命中则再读对应模版。
2. 对齐表分成「沿用」和「本系统差异」。沿用项不重新设计。
3. 确认后的差异写进该项目的 PRD。
4. 设计阶段不再重开已沿用的能力和交互，只为本系统差异做技术方案。

## 改模版

只属于一个系统的差异留在该项目 PRD。

以后每个新系统都要沿用的改动，改本目录里的模版，再按 [project-onboarding.md](../project-onboarding.md) §3.5 同步到各项目。业务项目里的 `docs/product-templates/` 是同步来的副本，不在单个项目里改底稿。
