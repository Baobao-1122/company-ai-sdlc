# CP 决策判据（Decision Rubrics）

> **文档 ID：** `RUBRICS-v1`  
> **策略：** 质量 → 安全 → 效率  
> **受众：** Cursor Agent + 研发人员  
> **配套：** [human-checkpoints.md](human-checkpoints.md) · [agent-active-guidance.md](agent-active-guidance.md)  
> **最后更新：** 2026-08-19

---

## 1. 为什么需要判据

每个 CP 除「请你回复 1/2/3」外，必须展示 **你要判什么、Allow/Stop 标准、Agent 自检结果**，避免形式上过卡点、实质上未决策。

---

## 2. 决策包结构（每个 CP 必须）

Agent 在 `⏸ CP-xx` 前**必须**按序输出：

| 块 | 内容 |
|----|------|
| **① 本卡点目的** | 1 句话：为什么停 |
| **② 判断要点** | 3～5 条（通用 + 项目扩展），每条含 Allow / Stop 标准 |
| **③ Agent 自检** | 逐条 `✅` / `❌` / `⚠️` + 一句证据 |
| **④ Agent 推荐** | **Allow** / **Stop** / **有条件 Allow** + 理由 |
| **⑤ 请你回复** | 编号选项（与 human-checkpoints 一致） |

**禁止：** 只有选项、无判据；只有判据、无自检；推荐与自检矛盾且不说明。

---

## 3. 通用判据（所有 Web 项目）

### CP-01 需求对齐

| # | 判断要点 | Allow（可确认） | Stop（应修改/暂停） |
|---|----------|-----------------|---------------------|
| 1 | 范围与 PRD/工单一致 | 目标、边界与文档一致 | 范围模糊或与 PRD 冲突 |
| 2 | 验收可测 | 有明确输入/输出/验收标准 | 只有「做好一点」类描述 |
| 3 | 外部依赖已说明 | 缺数据/接口已标明影响 | 静默 mock、未说明第三方依赖 |
| 4 | 安全/生产边界 | 不涉及未授权 deploy/写生产库 | 触及 CP-10 类操作未单独审批 |

**默认推荐：** 四项均 ✅ 或仅 ⚠️→ **Allow**；任一项 ❌→ **Stop**

---

### CP-02 设计拆分

| # | 判断要点 | Allow | Stop |
|---|----------|-------|------|
| 1 | 改动范围最小 | 文件清单精确、无无关文件 | 范围过大或未声明敏感路径 |
| 2 | 验收命令完整 | 含 `test:harness:ci` 及项目规定追加命令 | 缺 harness 或敏感路径未加 profile |
| 3 | commit 可拆分 | 一 commit 一功能，类型不混 | feat+fix 混在一个 commit |
| 4 | 文档同步已计划 | 行为/API 变更对应 docs | 改 API 未提 docs |
| 5 | 数据库变更计划 | 不涉及数据库结构，或已列 migration prepare/apply、应用环境、验证与回滚方式 | 改 schema 但未计划 migration，或只准备文件而未计划应用验证 |
| 6 | 业务数据影响计划 | 未命中数据影响面（查询/筛选语义、归属/归因、聚合、金额/电量口径、可见范围）并简述理由；或已列**只读**抽样对账计划（样本、指标、基线、通过标准） | 明显命中却写 N/A；计划含 INSERT/UPDATE/DELETE/「校验时修数」；未说明校验后只出结论与问题 |

---

### CP-03 外部依赖阻塞

| # | 判断要点 | 说明 |
|---|----------|------|
| 1 | 缺什么 | 接口/字段/环境 |
| 2 | 影响什么 | 页面/KPI/验收 |
| 3 | 可选路径 | mock（须标风险）/ 延后 / 等联调 / 缩小范围 |

**推荐：** 由你选 1～4 号回复；Agent 不得替你做默认选择。

---

### CP-04 范围外问题

| # | 判断要点 | Allow 扩展范围 | Stop 不扩展 |
|---|----------|----------------|-------------|
| 1 | 问题真实性 | Agent 已给出位置与现象 | 未验证就声称有 bug |
| 2 | 与本次任务关系 | 不修会导致本次无法验收 | 完全无关 |

---

### CP-05 实现 + 验证

| # | 判断要点 | Allow 进入提交 | Stop |
|---|----------|----------------|------|
| 1 | Harness | `test:harness:ci`（或 AGENTS 规定命令）✅ | ❌ 或未跑 |
| 2 | 改动与 CP-02 一致 | 未超范围 | 有未声明文件改动 |
| 3 | 手动验收步骤 | Agent 已给出 | 缺失 |
| 4 | 数据库结构一致性 | 不涉及数据库结构，或 migration 已纳入版本管理、应用至验收环境并通过结构检查与依赖 API 冒烟 | schema 已变更但无 migration，或 migration 仅准备未应用、验收库未更新、依赖 API 未验证 |
| 5 | 业务数据抽样对账 | 未命中数据影响面；或已按 CP-02 计划完成**只读**核对，并给出结论与问题清单（含数字证据） | 缺对账证据；核对过程改删了业务数据；只说「已对过」无结论/问题表 |

---

### CP-06 步骤 1 · Code Review

| # | 判断要点 | Allow 确认提交 | Stop 先修 |
|---|----------|----------------|-----------|
| 1 | Blocker/High | 无 | 有 |
| 2 | 审查结论 | 总体 ✅ 或 ⚠️ 且你接受 | ❌ 建议先修 |
| 3 | 代码质量 | 优/良 | 需改进且影响可维护性/安全 |
| 4 | 风险等级 | 低/中且可说明 | 高 |
| 5 | Next.js middleware/proxy 改写 Response（若 diff 命中） | 透传 `response.body` 且保留 `Content-Type`；无 auth Cookie 双写 | 读 body 重建为 string 且未拷贝 Content-Type；或 middleware 与 `/api/auth` 双写 |
| 6 | 业务数据对账证据（若本次命中数据影响面） | CP-05 有只读核对结论与问题清单；diff 无「对账脚本写库」 | 无证据；或以校验名义含写库/删库逻辑 |

见 [code-review.md](code-review.md) 审查结论表、**§8 Response 改写红线**与 **§9 业务数据只读对账**。

---

### CP-06 步骤 2 · Commit 确认

| # | 判断要点 | Allow | Stop |
|---|----------|-------|------|
| 1 | 一 commit 一事 | 拆分正确 | 类型混合 |
| 2 | message 规范 | 中文、类型正确 | 无意义 message |
| 3 | 无调试残留 | 无 console.log、无注释废码 | 有 |

---

### CP-07 推送

| # | 判断要点 | Allow | Stop |
|---|----------|-------|------|
| 1 | 分支 | 非 dev/main 或已授权 | 受保护分支且无授权 |
| 2 | 本地已 commit | 是 | 仅有未提交改动 |

---

### CP-08 合并 / PR

| # | 判断要点 | Allow | Stop |
|---|----------|-------|------|
| 1 | 自测 | harness + Review 已完成 | 未过 CP-05/06 |
| 2 | 变更摘要 | Agent 已说明 | 缺失 |
| 3 | 负责人 | 用户明确确认 | 未确认 |

---

### CP-09 下一需求

| # | 判断要点 | 说明 |
|---|----------|------|
| 1 | 当前任务 | CP-05 已完成 |
| 2 | 下一项 | 你指定 FU/工单，从 CP-01 重新开始 |

---

### CP-10 高风险

| # | 判断要点 | Allow | Stop |
|---|----------|-------|------|
| 1 | 操作类型 | deploy/SSH/写生产/删库 | — |
| 2 | 授权 | 负责人明确口头/书面授权 | 无授权 |
| 3 | 回滚 | 有回滚或备份说明 | 无 |

## 4. 项目扩展（通用性）

通用判据在上表；**项目特有**判据写在项目 `AGENTS.md` § **CP 判断扩展**，Agent 在对应 CP 的「② 判断要点」中**追加**行，不删除通用行。

模板：[templates/decision-rubrics-project.template.md](../templates/decision-rubrics-project.template.md)

示例（运营平台类项目）：

| CP | 项目追加要点 |
|----|--------------|
| CP-01 | 零浩/奥能数据缺口须单独一行 |
| CP-02 | 改 `lib/evcs/` 须读模块 AGENTS |
| CP-06 | L2 路径 api/auth/evcs |
| CP-10 | 禁止 Mac 写 ECS/RDS |

---

## 5. 优先级（Agent 推荐冲突时）

1. **安全 / CP-10** → 默认 Stop  
2. **Blocker/High Review** → 默认 Stop  
3. **Harness 失败** → 默认 Stop  
4. **Medium/Low** → 可有条件 Allow，须你明确「忽略：理由」  
5. **效率** → 不得 override 1～3
