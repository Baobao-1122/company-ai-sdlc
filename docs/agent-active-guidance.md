# AI 主动引导手册（Agent-Led Workflow）

> **文档 ID：** `GUIDANCE-v1`  
> **策略：** AI 主导流程，人工在 CP 处回复判断  
> **配套：** [human-checkpoints.md](human-checkpoints.md)  
> **最后更新：** 2026-07-17

---

## 1. 协作模型

```
AI：宣布阶段 → 执行 → 到达 CP → 主动提问 + 给出回复选项 → 停
人：跟着流程走 → 在 CP 处读选项 → 回复一句话 → 不需要自己猜「该不该介入」
```

**原则：**

- **AI 负责「什么时候停、问什么、下一步是什么」**
- **人负责「确认、否决、选方案、授权高风险操作」**
- 人**不需要**记住 CP 编号；看到 `⏸` 和「请你回复」即介入

---

## 2. 会话开场（Agent 必须做）

用户提出任何**开发类任务**（新功能、改 bug、重构）时，Agent **第一句**须包含：

```markdown
📍 **AI-SDLC 工作流已启用**

我将按 **需求 → 设计 → 实现 → 验证 → （你要求时）提交** 引导你完成。

**当前建议：** 从 **阶段 1 · 需求对齐** 开始。

请告诉我本次要做哪一条（PRD 章节 / 工作清单条目 / 一句话描述）；
若需求已很清楚且你只想小改，也可直接说「小改动：xxx，跳过对齐」。
```

**小改动例外：** 用户明确说「小改动 / 一行 fix / 改 typo」→ 可跳过 CP-01，但仍须在 **CP-05** 停。

---

## 3. 阶段进度条（每条回复开头）

进行 SDLC 任务时，Agent 非 CP 回复**开头**加一行：

| 阶段 | 进度条 |
|------|--------|
| 需求对齐 | `📍 阶段 1/5 · 需求对齐` |
| 设计拆分 | `📍 阶段 2/5 · 设计拆分` |
| 编码实现 | `📍 阶段 3/5 · 编码实现` |
| 验证门禁 | `📍 阶段 4/5 · 验证门禁` |
| 等待你指示 | `📍 阶段 5/5 · 等待你的指示` |

---

## 4. 各 CP 主动引导模板（Agent 必须使用）

每个 CP 回复须含 **4 块**：`当前阶段` · `我已完成` · `请你回复` · `⏸ CP-xx`

### CP-01 需求对齐后

```markdown
📍 阶段 1/5 · 需求对齐 · **等待你的确认**

### 我已完成
- 阅读 AGENTS.md / PRD 相关章节
- 输出下方需求对齐表

（对齐表）

### 请你回复（任选其一）
1. **「确认」** — 我将进入 **阶段 2 · 设计拆分**
2. **「修改：…」** — 我调整对齐表，仍停在 CP-01
3. **「暂停」** — 结束本次任务

⏸ **CP-01 需求对齐暂停**
```

### CP-02 设计拆分后

```markdown
📍 阶段 2/5 · 设计拆分 · **等待你开始实现的许可**

### 我已完成
- 列出改动文件、依赖、验收命令、建议 commit 拆分

（设计内容）

### 请你回复（任选其一）
1. **「开始实现」** — 我进入 **阶段 3 · 编码实现**
2. **「调整范围：…」** — 我修改设计，仍停在 CP-02
3. **「暂停」** — 结束本次任务

⏸ **CP-02 设计暂停**
```

### CP-03 外部依赖阻塞

```markdown
📍 阶段 3/5 · 编码实现 · **外部依赖阻塞**

### 我发现
- 缺 xxx 接口/数据/环境
- 影响：…

### 请你回复（必选其一）
1. **「mock 继续」** — 我用 mock 并明确标注精度风险
2. **「延后」** — 停止实现，记录到 docs 待定
3. **「等联调」** — 我先做不依赖部分，其余挂起
4. **「其他：…」** — 按你的方案

⏸ **CP-03 依赖阻塞暂停**
```

### CP-04 范围外问题

```markdown
📍 阶段 3/5 · 编码实现 · **发现范围外问题**

### 我发现
- 问题：…
- 涉及文件：（不在本次声明范围内）

### 请你回复（必选其一）
1. **「一起修」** — 扩展本次范围，我更新设计后继续
2. **「只修 xxx」** — 仅修指定部分
3. **「跳过」** — 我记录问题，本次不动

⏸ **CP-04 范围外暂停**
```

### CP-05 实现 + 验证后

```markdown
📍 阶段 4/5 · 验证完成 · **等待你的下一步指示**

### 我已完成
- 改动摘要：…
- 验证结果：（harness 表格）
- 手动验收步骤：…

### 请你回复（任选其一）
1. **「提交」** — 我进入 **sdlc-review**（CP-06 · 每次 commit 必跑 Code Review）
2. **「继续改：…」** — 我按反馈修改，完成后再次 CP-05
3. **「下一项：…」** — 本次结束（CP-09），新任务从阶段 1 开始
4. **「暂停」** — 保留改动，不提交

⏸ **CP-05 完成暂停**
```

### CP-06 · 步骤 1/2 · Code Review（每次 commit 必跑）

```markdown
📍 阶段 5/5 · Code Review 完成 · **等待你对 Review 的决定**

### Code Review（Bugbot [+ Security]）
| 严重度 | 位置 | 发现 |
| … | … | … |

### 请你回复（必选其一）
1. **「确认提交」** — 进入 CP-06 步骤 2（展示 commit 计划）
2. **「先修 review」** — 修完重跑 harness + Review
3. **「忽略：…」** — 须说明理由
4. **「暂停」**

⏸ **CP-06 · 步骤 1/2 · Code Review 暂停**
```

### CP-06 · 步骤 2/2 · Commit 确认

```markdown
📍 阶段 5/5 · Commit 确认

### 拟提交
- git status / 拆分 / message

### 请你回复
1. **「确认提交」** — 执行 git commit
2. **「调整 message：…」**

⏸ **CP-06 · 步骤 2/2 · Commit 确认暂停**
```

### CP-07～CP-10

见 [human-checkpoints.md](human-checkpoints.md) §5；同样须含 **「请你回复」** 选项列表。

## 5. 进入下一阶段时（Agent 主动预告）

用户通过 CP 后，Agent **下一条**回复开头加：

```markdown
✅ 已收到「确认 / 开始实现 / …」→ 进入 **阶段 N · xxx**

**接下来我会：** …
**预计下次需要你介入：** CP-xx（xxx 完成后）
```

示例：

```markdown
✅ 已收到「确认」→ 进入 **阶段 2 · 设计拆分**

**接下来我会：** 列出改动文件与验收方式，完成后在 **CP-02** 请你回复「开始实现」。
```

---

## 6. 人工无需介入的时段（Agent 应主动说明）

进入 **阶段 3 · 编码** 且 CP-02 已通过时，Agent 可先说一句：

```markdown
📍 阶段 3/5 · 编码实现

**接下来我会自动完成（无需你回复）：** 在已声明文件内改代码 → 跑 test:harness:ci  
**预计下次需要你介入：** 验证完成后 **CP-05**
```

这样人知道「这段时间可以先忙别的」。

## 7. 人工速查（只看这一表）

| 看到 Agent 说什么 | 你该做什么 |
|-------------------|-----------|
| `📍 阶段 1/5` + 对齐表 + `⏸ CP-01` | 读表 → 回复「确认」或「修改：…」 |
| `📍 阶段 2/5` + 文件清单 + `⏸ CP-02` | 读范围 → 回复「开始实现」 |
| `无需你回复` + 阶段 3 | **不用管**，等 CP-05 |
| `⏸ CP-05` + 验证结果 | 回复「提交 / 继续改 / 下一项」 |
| `⏸ CP-06 · 步骤 1/2` | Review 后：「确认提交 / 先修 / 忽略」 |
| `⏸ CP-06 · 步骤 2/2` | 回复「确认提交」 |
| `⏸ CP-07` | 回复「推送」 |
| 任何 `⏸ CP-10` | 谨慎，需负责人授权 |

---

## 8. Agent 禁止

1. 到达 CP **不带「请你回复」选项列表**
2. CP 处 **开放式**「你觉得呢？」— 必须给编号选项
3. 跳过 CP 预告（进入阶段 3 不说明何时再找人）
4. 用户未回复就进入下一阶段
