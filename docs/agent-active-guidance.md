# AI 主动引导手册（Agent-Led Workflow）

> **文档 ID：** `GUIDANCE-v1`  
> **策略：** AI 主导流程，人工在 CP 处回复判断  
> **配套：** [human-checkpoints.md](human-checkpoints.md) · [decision-rubrics.md](decision-rubrics.md)  
> **最后更新：** 2026-07-27

---

## 1. 协作模型

```
AI：宣布阶段 → 执行 → 到达 CP → 主动提问 + 给出回复选项 → 停
人：跟着流程走 → 在 CP 处读选项 → 回复一句话 → 不需要自己猜「该不该介入」
```

**原则：**

- **AI 负责「什么时候停、问什么、下一步是什么」**
- **人负责「确认、否决、选方案、授权高风险操作」**
- 人**不需要**记住 CP 编号；看到 `⏸` 和「请你回复」即介入

---

## 2. 会话开场（Agent 必须做）

用户提出任何**开发类任务**（新功能、改 bug、重构）时，Agent **第一句**须包含：

```markdown
📍 **AI-SDLC 工作流已启用**

我将按 **需求 → 设计 → 实现 → 验证 → （你要求时）提交** 引导你完成。

**当前建议：** 从 **阶段 1 · 需求对齐** 开始。

请告诉我本次要做哪一条（PRD 章节 / 工作清单条目 / 一句话描述）；
若需求已很清楚且你只想小改，也可直接说「小改动：xxx，跳过对齐」。
```

**小改动例外：** 用户明确说「小改动 / 一行 fix / 改 typo」→ 可跳过 CP-01，但仍须在 **CP-05** 停。

**Task State：** 开发任务须维护 `.sdlc/task-state.yaml`（见 [task-state.md](task-state.md)）。**新 Chat** 或用户说「续任务」时，Agent **第一句 Read state** 并汇报断点；**不新增** mandatory 人工步骤。

---

## 3. 阶段进度条（每条回复开头）

进行 SDLC 任务时，Agent 非 CP 回复**开头**加一行：

| 阶段 | 进度条 |
|------|--------|
| 需求对齐 | `📍 阶段 1/5 · 需求对齐` |
| 设计拆分 | `📍 阶段 2/5 · 设计拆分` |
| 编码实现 | `📍 阶段 3/5 · 编码实现` |
| 验证门禁 | `📍 阶段 4/5 · 验证门禁` |
| **Reflection · P1** | `🔄 Reflection · P1 预 Review（CP-05 前）` |
| 等待你指示 | `📍 阶段 4/5 · 验证完成 · 等待你的指示` |
| **Reflection · CP-06** | `🔄 Reflection · CP-06 · commit 前 Code Review` |
| 等待 commit | `📍 阶段 5/5 · 等待你的指示` |

## 4. 各 CP 决策包模板（Agent 必须使用）

每个 CP 须含 **5 块**（详见 [decision-rubrics.md](decision-rubrics.md)）：

`①本卡点目的` · `②判断要点` · `③Agent自检` · `④Agent推荐` · `⑤请你回复` · `⏸ CP-xx`

判据全文见 `decision-rubrics.md` §3；项目追加见 `AGENTS.md` §CP 判断扩展。

### CP-01 示例（其他 CP 同结构）

```markdown
📍 阶段 1/5 · 需求对齐 · **等待你的确认**

### ① 本卡点目的
确认需求范围与验收后再设计/编码，避免做错方向。

### ② 判断要点
| # | 要点 | Allow | Stop |
| 1 | 范围与 PRD 一致 | … | … |
| 2 | 验收可测 | … | … |
| 3 | 外部依赖已说明 | … | … |
（+ 项目 AGENTS §CP 判断扩展 若有）

### ③ Agent 自检
| # | 结果 | 说明 |
| 1 | ✅ | … |
| 2 | ⚠️ | … |

### ④ Agent 推荐
**Allow** — 四项无 ❌，可进入设计。（或 **Stop** — 原因…）

### ⑤ 请你回复
1. **「确认」**  2. **「修改：…」**  3. **「暂停」**

⏸ **CP-01 需求对齐暂停**
```

### CP-02～CP-05、CP-07～CP-10

结构同 CP-01；判据表用 `decision-rubrics.md` §3 对应章节，不得省略 ②③④。

### CP-06 · 步骤 1/2 · Code Review（每次 commit 必跑）

**必须含「审查结论」表** — 见 [code-review.md](code-review.md) §5；判据见 [decision-rubrics.md](decision-rubrics.md) §3 CP-06。

```markdown
📍 阶段 5/5 · Code Review 完成 · **等待你对 Review 的决定**

## 审查结论（必填）

| 项 | 内容 |
| **总体结论** | ✅ 可提交 / ⚠️ 可提交但有保留 / ❌ 建议先修 / ⏭ 未完成 |
| **问题数量** | Blocker:0 High:0 … 或 无问题 |
| **代码质量** | 优/良/需改进 — … |
| **风险等级** | 低/中/高 — … |
| **Agent 建议** | 确认提交 / 先修 |

### 一句话摘要
…

### 具体问题
（表格或「无」+ 无问题说明）

### 请你回复（必选其一）
1. **「确认提交」**  2. **「先修 review」**  3. **「忽略：…」**  4. **「暂停」**

⏸ **CP-06 · 步骤 1/2 · Code Review 暂停**
```

### CP-06 · 步骤 2/2 · Commit 确认

```markdown
📍 阶段 5/5 · Commit 确认

### 拟提交
- git status / 拆分 / message

### 请你回复
1. **「确认提交」** — 执行 git commit
2. **「调整 message：…」**

⏸ **CP-06 · 步骤 2/2 · Commit 确认暂停**
```

### CP-07～CP-10

见 [human-checkpoints.md](human-checkpoints.md) §2（CP 定义）与 [decision-rubrics.md](decision-rubrics.md) §3；须含完整决策包（②③④ 不可省）。

## 5. 进入下一阶段时（Agent 主动预告）

用户通过 CP 后，Agent **下一条**回复开头加：

```markdown
✅ 已收到「确认 / 开始实现 / …」→ 进入 **阶段 N · xxx**

**接下来我会：** …
**预计下次需要你介入：** CP-xx（xxx 完成后）
```

示例：

```markdown
✅ 已收到「确认」→ 进入 **阶段 2 · 设计拆分**

**接下来我会：** 列出改动文件与验收方式，完成后在 **CP-02** 请你回复「开始实现」。
```

## 6. 人工无需介入的时段（Agent 应主动说明）

进入 **阶段 3 · 编码** 且 CP-02 已通过时，Agent 可先说一句：

```markdown
📍 阶段 3/5 · 编码实现

**接下来我会自动完成（无需你回复）：** 在已声明文件内改代码 → 若改 schema，按 CP-02 计划执行 migration 链 → 若命中业务数据影响面，按计划做**只读**抽样对账并整理结论与问题 → 跑 test:harness:ci → 若命中 P1，先发 **`🔄 Reflection · P1` 开场话术** 再跑 Bugbot（见 [code-review.md](code-review.md) §11）
**预计下次需要你介入：** 验证与 Reflection 完成后 **CP-05**
```

这样人知道「这段时间可以先忙别的」。

若本次修改数据库 schema，Agent 的自动执行链必须扩展为：

```text
migration prepare（生成或手写并检查）→ 应用至目标验收库 → 结构一致性检查
→ 依赖新结构的 API/数据访问冒烟
→（若同时命中业务数据影响面）只读抽样对账 → 结论与问题清单
→ test:harness:ci
→（若命中 P1）**🔄 Reflection · P1**（§11 开场 → Bugbot → §11 完成块）
→ CP-05 汇报迁移证据、对账结论（如有）、P1 结论（如有）与手动页面验收步骤
```

数据库变更链与只读对账每一步仅在上一步成功后执行；任一步失败都必须停止后续步骤（包括 harness），并在 CP-05 标为未完成、推荐 **Stop**。不得用“migration 文件已准备”代替实际应用验证。

若本次**未改 schema**但命中**业务数据影响面**（查询/筛选语义、归属、聚合、金额/电量口径、可见范围等），执行链为：

```text
按 CP-02 抽样计划做只读核对（查询/导出/对比）
→ 输出结论与问题清单（含数字证据）
→ 不得 INSERT/UPDATE/DELETE 业务数据
→ 需修数时只报告，另开任务并单独授权
→ test:harness:ci
→（若命中 P1）**🔄 Reflection · P1** → CP-05
```

结构门禁与业务数据门禁互不替代；**禁止**在对账未完成时先跑 harness。Harness 通过不等于业务结果已核对。

用户说「提交」后，须先发 **`🔄 Reflection · CP-06` 开场话术** 再跑 Bugbot（§11.2），完成后 **`🔄 Reflection · CP-06 · 完成`** + CP-06 步骤 1。

## 6.1 Reflection 用户可见（硬性）

进入 **P1** 或 **CP-06** 互查前，Agent **必须**在聊天里标明 `🔄 Reflection`（完整模板见 [code-review.md](code-review.md) §11）。

| 你应看到 | 含义 | 你要做什么 |
|----------|------|------------|
| `🔄 Reflection · P1 …` | harness 后的早期互查 | **无需回复**，等完成块 + CP-05 |
| `🔄 Reflection · P1 · 完成` | P1 结论已出 | 读结论，在 CP-05 决策 |
| `ℹ️ Reflection · P1 未触发` | 本轮跳过 P1 | 正常进入 CP-05 |
| `🔄 Reflection · CP-06 …` | commit 前最后一轮互查 | **无需回复**，等 CP-06 步骤 1 |
| `🔄 Reflection · CP-06 · 完成` | 审查结论 | CP-06 步骤 1 回复 |

**禁止** Agent 静默跑 Bugbot 而不告知「本轮是 Reflection」。

## 7. 人工速查（只看这一表）

| 看到 Agent 说什么 | 你该做什么 |
|-------------------|-----------|
| `📍 阶段 1/5` + 对齐表 + **②判据/③自检/④推荐** + `⏸ CP-01` | 读判据与自检 → 回复「确认」或「修改：…」 |
| `📍 阶段 2/5` + 设计 + 决策包 + `⏸ CP-02` | 读范围与判据 → 回复「开始实现」 |
| `无需你回复` + 阶段 3 | **不用管**，等 CP-05 |
| `🔄 Reflection · P1 …` | **Reflection 轮次**，不用管，等完成 + CP-05 |
| `⏸ CP-05` + 验证与 Reflection | 回复「提交 / 继续改 / 下一项」 |
| `🔄 Reflection · CP-06 …` | **Reflection 轮次**，不用管，等 CP-06 步骤 1 |
| `⏸ CP-06 · 步骤 1/2` | Reflection 结论后：「确认提交 / 先修 / 忽略」 |
| `⏸ CP-06 · 步骤 2/2` | 回复「确认提交」 |
| `⏸ CP-07` | 回复「推送」 |
| 任何 `⏸ CP-10` | 谨慎，需负责人授权 |

## 8. Agent 禁止

1. 到达 CP **不带完整决策包**（缺 ②③④ 任一块）
2. **Reflection 轮次未用 `🔄 Reflection` 告知用户**（见 [code-review.md](code-review.md) §11）
3. CP 处 **开放式**「你觉得呢？」— 必须给编号选项
4. 跳过 CP 预告（进入阶段 3 不说明何时再找人）
5. 用户未回复就进入下一阶段
