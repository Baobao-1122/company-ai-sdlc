# 阶段 2：设计拆分

**对应 Skill：** `sdlc-design`

## 目标

将已确认的需求拆为可独立实现、可独立验收的任务。

## Agent 执行步骤

1. 列出待改文件（精确路径）
2. 列出依赖（DB 迁移、新 API、新组件）
3. 列出验收命令（如 `test:harness:ci`、手动步骤）
4. 估算是否需要拆多个 commit

涉及数据库结构变更时，还必须列出：

- migration prepare 方式（工具生成，或手写并检查 journal/manifest）
- 应用迁移的目标验收环境（本地、测试或隔离集成库）
- 迁移状态/结构一致性检查命令
- 至少一个依赖新结构的 API 或数据访问冒烟步骤
- 失败回滚或恢复方式

涉及**业务数据影响面**时（查询/筛选语义、归属/归因、聚合统计、金额/电量口径、可见数据范围等，含「只改逻辑不改 schema」），还必须列出**只读**抽样对账计划：

- 样本范围（客户/站点/日期窗口等）
- 对比指标（笔数、电量、金额等 1～3 个）
- 基线来源（改前查询结果，或外部真相如 Excel/对方对账单）
- 通过标准（一致 / 差异可解释且负责人接受）
- 明确：**校验只读**——禁止 INSERT/UPDATE/DELETE；校验后只输出**结论与问题清单**；修数另开任务并单独授权

未命中数据影响面时，须写「无数据影响」并简述理由；禁止在明显命中时写 N/A。

涉及**配置、环境变量、业务常量或错误/提示文案**时，还必须列出**配置与常量计划**：

- 是否新增或变更 env、阈值/枚举、错误码或集中定义的提示文案
- 代码中的存放路径（如 `lib/constants.ts`、`lib/errors.ts`；禁止在 route/service 内 inline 新字面量）
- 若新增 env：须计划同步 `.env*.example`（若有）与 `docs/deploy.md`（见 `docs-sync` Rule）
- 不涉及则写「无配置变更」并简述理由

涉及**新增或升级 npm 生产依赖**时，还必须列出**依赖与库计划**：

- 包名、用途、未选替代方案的原因（若有）
- 体积/维护/许可等简要评估
- 用户 **「开始实现」** 视为对本表所列依赖的安装确认
- 不涉及则写「无新 npm 生产依赖」

涉及 **API、auth/RBAC、金额/计价、导出范围或敏感读路径**时，还必须列出**安全与输入校验计划**：

- Zod（或等价）schema 位置；服务端权限/计价校验点
- 1～2 条**安全冒烟**（如越权、非法 body 应 4xx）
- **生产库：** 本次无生产写操作；若任务涉及生产改数 → 仅 **CP-10**，默认禁止 Agent 执行

## 输出模板

```markdown
## 设计拆分：FU-xxx

### 改动范围
- `src/app/api/.../route.ts` — 新增 GET 接口
- `src/db/schema.ts` — 新增 xxx 表

### 依赖
- 无外部接口依赖 / 依赖零浩 xxx 字段（需确认）
- DB：migration → 验收库应用 → 结构检查 → API 冒烟（如不涉及则写「无」）

### 业务数据影响（条件必填）
- 是否命中：是 / 否（理由）
- 抽样计划（命中时）：样本…；指标…；基线…；通过标准…
- 只读红线：校验禁止改删数据；产出为结论与问题

### 配置与常量（条件必填）
- 是否命中：是 / 否（理由）
- 路径（命中时）：常量/错误码文件…
- env 文档（命中 env 时）：example + deploy 同步计划

### 依赖与库（条件必填）
- 是否新增或升级 npm 生产依赖：是 / 否
- 包名与用途（命中时）：…
- 「开始实现」= 确认上表依赖

### 安全与输入校验（条件必填）
- 是否改 API/auth/金额/导出：是 / 否
- schema 与权限点（命中时）：…
- 安全冒烟（命中时）：…
- 生产库写：无 / 须 CP-10

### 验收
- [ ] `pnpm test:harness:ci`
- [ ] DB 变更：migration 已应用且依赖 API 冒烟通过
- [ ] 数据影响：只读抽样对账已完成并给出结论与问题（如不涉及则写「无」）
- [ ] 配置与硬编码：与 CP-02 计划一致（如不涉及则写「无」）
- [ ] 安全：冒烟与数据红线（生产无擅自写库）
- [ ] npm 依赖：与 CP-02/CP-03 一致（如不涉及则写「无」）
- [ ] 手动：登录后可见 xxx 列表

### 建议 commit 拆分
1. `feat(xxx): 新增 schema 与 migration`
2. `feat(xxx): 实现 API 与页面`
```

## 禁止

- 改动范围过大（一次改 10+ 文件无说明）
- 不声明外部数据依赖
- 修改 schema 却未声明 migration、应用环境与验证步骤
- 命中业务数据影响面却无只读抽样计划，或计划中含「校验时修数/删数」
- 明显会动 env/常量/错误文案却无「配置与常量」设计块
- 拟新增 npm 生产依赖却无「依赖与库」设计块
- 改 API/auth/金额等却无「安全与输入校验」设计块
