# 人工确认暂停点（Human Checkpoints）

> **文档 ID：** `CHECKPOINTS-v1`  
> **策略：** 稳健优先（低风险）  
> **受众：** Cursor Agent + 研发人员  
> **最后更新：** 2026-08-03

---

## 1. 总则

**默认模式：AI 主动引导 + 人工在 CP 介入。** Agent 负责宣布阶段、提问、给出回复选项；人只需在 `⏸` 处按选项回复。

**半自动执行：** Agent 可在**已确认范围内**连续读文档、写代码、跑测试；在 **CP 暂停点必须停止**，输出 **决策包**（判据 + 自检 + 推荐 + 编号选项）。

**禁止：** Agent 自行跳过 CP、开放式甩锅（「你觉得呢？」）、自行 commit/push/合并。

**主动引导细则：** [agent-active-guidance.md](agent-active-guidance.md)  
**判断要点（Allow/Stop）：** [decision-rubrics.md](decision-rubrics.md)

---

## 2. 暂停点一览

| ID | 名称 | 触发时机 | Agent 必须做什么 | 等人说什么 |
|----|------|----------|------------------|------------|
| **CP-01** | 需求对齐后 | 输出需求对齐表后 | **停止**；不写代码、不拆设计 | 「确认」「OK」「按这个做」 |
| **CP-02** | 设计拆分后 | 输出改动范围/验收/ commit 计划；涉及 schema 时含 migration 应用与验证计划 | **停止**；不写代码 | 「开始实现」「可以动手」 |
| **CP-03** | 外部依赖阻塞 | 发现缺接口/数据/权限/环境 | **停止**；说明影响与选项 | 「用 mock 继续」「先不做」「等联调」 |
| **CP-04** | 范围外问题 | 发现未提及的 bug、需改声明外文件 | **停止**；报告问题，不顺手修 | 「一起修」「只修 xxx」「跳过」 |
| **CP-05** | 实现+验证后 | 编码完成且验证命令已有明确结果；涉及 schema 时数据库变更链已执行或已确认环境阻塞 | **停止**；汇报结果，任一步失败时推荐 **Stop** | 「提交」「继续改 xxx」「下一项」 |
| **CP-06** | **每次 commit 前** | ① Code Review ② commit 计划 | **两步都停**；见 [code-review.md](code-review.md) | 步骤1：「确认提交/先修/忽略」步骤2：「确认提交」 |
| **CP-07** | 推送前 | 任何 `git push` 前 | 汇报分支与远端 | 「推送」 |
| **CP-08** | 合并 dev / PR | merge、PR merge、push dev 前 | 说明源分支、变更摘要 | 「合并」「开 PR」 |
| **CP-09** | 下一需求项 | 当前任务在 CP-05 已完成 | **停止** | 「做下一项 FU-xxx」 |
| **CP-10** | 高风险操作 | deploy、SSH、写 ECS/RDS、删库 | **停止** | 负责人明确授权 |

## 3. 可自动执行（无需暂停）

以下条件**同时满足**时，Agent **不必**在步骤间等人：

| 动作 | 条件 |
|------|------|
| 读 AGENTS.md / docs | 任何时候 |
| 在同一任务内改**已声明**的文件 | CP-02 已通过 |
| migration prepare（生成或手写并检查）、应用至目标验收库、结构检查与依赖 API 冒烟 | CP-02 已通过且本次修改 schema；按设计顺序执行 |
| 跑 `test:harness:ci` 等项目验证命令 | 未改 schema，或数据库变更链已全部通过；在 CP-05 汇报前执行 |
| 同步更新与本次改动相关的 docs | CP-02 已通过 |
| 修复实现引入的 lint/类型错误 | 不扩大文件范围 |

## 4. 标准流程与 CP 位置

```
[用户提任务]
     │
     ▼
┌─ 需求对齐 ─────────────────────────► CP-01 停 ◄── 等人确认
│
     ▼
┌─ 设计拆分 ─────────────────────────► CP-02 停 ◄── 等人「开始实现」
│
     ▼
┌─ 编码实现 ───┬─ 遇外部依赖 ────────► CP-03 停
│              └─ 遇范围外问题 ──────► CP-04 停
│
     ▼
┌─ 验证门禁（DB 变更链如适用 → harness）► CP-05 停 ◄── 等人决定提交/下一项
│
     ├─ 用户说「提交」───────────────► CP-06 步骤1 Code Review（Bugbot）
     │                                      ↓
     │                               CP-06 步骤2 commit 确认
     ├─ 用户说「推送」───────────────► CP-07 停
     ├─ 用户说「合并/PR」───────────► CP-08 停
     └─ 用户说「下一项」─────────────► CP-09 → 回到需求对齐
```

---

## 5. Agent 暂停话术（必须使用）

每个 CP 结束时，Agent 回复**必须**包含完整 **决策包**（见 [decision-rubrics.md](decision-rubrics.md) §2）：

`①目的` · `②判断要点` · `③Agent自检` · `④Agent推荐` · `⑤请你回复` · `⏸ CP-xx`

| CP | 结尾必须包含 |
|----|-------------|
| CP-01～10 | 决策包五块 + `⏸ CP-xx`；**禁止**仅有编号选项 |

## 6. 用户指令速查

| 你说 | Agent 行为 |
|------|-----------|
| 「对齐需求 xxx」 | 需求对齐 → **CP-01 停** |
| 「确认 / OK」 | 若停在 CP-01 → 可进入设计；若停在 CP-06 → 执行 commit |
| 「开始实现」 | 通过 CP-02 → 编码（范围内可自动跑验证） |
| 「跑 harness 验收」 | 验证阶段 → 完成后 **CP-05 停** |
| 「提交」 | 进入 **sdlc-review** → CP-06 步骤1 Review → 步骤2 commit |
| 「推送」 | **CP-07** → push |
| 「做下一项」 | 通过 CP-09 → 新需求从 CP-01 开始 |

**一条指令串多步（谨慎）：** 用户说「确认需求并开始实现，做完跑 harness」= 跳过 CP-01 口头确认、**仍须在 CP-05 停**；**不能**跳过 CP-05 自动 commit。
